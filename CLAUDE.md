# Хотелки

Личное PWA-приложение «Хотелки». Хостится на GitHub Pages, владелец пользуется им на iPhone
как приложением с главного экрана, в том числе без интернета.

## Зачем приложение

Это не список продуктов и не бюджет, а список желаний: не рядовых покупок, а того, что хочется
или планируется купить. Главная задача — открыть и сразу увидеть, что сейчас важнее.

## Как оно работает (так и задумано)

- Один общий список, без категорий и групп.
- Порядок задаёт только владелец, руками: перетаскивание за ручку ⋮⋮ (и стрелки с клавиатуры).
  Никакой авто-сортировки.
- У хотелки: название, примерная цена (необязательно), сколько её уже хотят («хочу 3 недели»).
- Кнопки «Купил» и «Перехотел» отправляют хотелку во вкладку «История» с датой и тем, сколько
  её хотели. Из истории можно вернуть — хотелка встаёт в конец списка.
- В «Истории» есть «Сохранить копию» (экспорт JSON через меню «Поделиться», запасной путь —
  скачивание файла) и «Восстановить» (импорт с подтверждением замены).
- Синхронизация между устройствами через секретный GitHub Gist (блок «Синхронизация» внизу
  «Истории»). Список по-прежнему живёт в localStorage и работает офлайн; при появлении сети
  он сливается с файлом `hotelki.json` в gist. Подключение — токен GitHub с доступом `gist`,
  на каждом устройстве один и тот же; второе устройство находит gist по имени файла.
- Сознательно отказались от: сумм и итогов, визуального выделения топа, напоминаний о старых
  хотелках. Не добавляй это без прямой просьбы.

## Файлы

- `index.html` — всё приложение: HTML + CSS + JS в одном файле, без сборки и фреймворков.
- `sw.js` — service worker для офлайна. Навигация: сначала сеть, потом кэш; своё и Google Fonts:
  кэш + фоновое обновление; прочие чужие адреса (GitHub API для синхронизации) не трогает.
- `manifest.json`, `icon-180.png` (apple-touch-icon), `icon-192.png`, `icon-512.png`
  (в том числе maskable).

Устройство `index.html`:

- `state = {v:2,items:[…]}`. Порядок «Хочу» задаёт поле `pos` (по возрастанию), а не порядок
  массива. `saveOrder(li)` после перетаскивания меняет `pos` только у сдвинутой хотелки —
  середина между соседями, — чтобы перестановки с разных устройств сливались.
- Любое изменение хотелки обязано обновить `updatedAt` (`touch()`): по нему идёт слияние.
  Удаление не убирает запись, а оставляет надгробие `{id,deleted:true,updatedAt}`, иначе
  синхронизация вернёт удалённое. Показывать — только `live()` / `wantItems()`.
- `load()` / `save()` / `persist()` — чтение и запись localStorage (`persist` ещё и планирует
  синхронизацию); `migrate()` приводит любой старый формат к v2. `render()` перерисовывает обе вкладки
  целиком и вызывается заново при возвращении приложения на передний план (обновляет «хочу N дней»).
- `dur()` — «сколько хочу» с русскими склонениями через `pl()`; `money()` — цена вида «≈ 12 000 ₽».
- Синхронизация: `runSync()` читает gist, сливает `merge()` по `id` (побеждает больший
  `updatedAt`), сохраняет локально и пишет в gist, только если там что-то изменилось.
  Запускается при открытии, возвращении в приложение, появлении сети и через 1,5 с после
  изменения. Настройки (токен, id gist) — в localStorage под ключом `'hotelki-sync'`, в копию
  они не попадают.
- Цвета — CSS-переменные в `:root`, тёмная тема через `prefers-color-scheme` и `data-theme`.

## Жёсткие правила

1. **Данные.** Живут в localStorage под ключом `'wishes-v1'`, текущий формат (v2)
   `{v:2,items:[{id,name,price,addedAt,status:'want'|'bought'|'gone',closedAt,pos,updatedAt}
   | {id,deleted:true,updatedAt}]}`. Тот же формат лежит в gist и в файлах копий.
   Прежний формат v1 — без `v`, `pos`, `updatedAt` и надгробий; его переводит `migrate()`,
   а исходные данные v1 при первой миграции сохраняются в `'wishes-v1-before-sync'`.
   Терять данные нельзя: если меняешь формат — пиши миграцию со всех старых форматов; ключ
   не трогай без миграции. Старые файлы копий и старое содержимое gist тоже должны
   восстанавливаться. Помни, что на другом устройстве может работать старая версия
   приложения: поля, которых она не знает, не должны ломать слияние.
2. **Кэш.** Если меняешь что-то кроме `index.html` (иконки, манифест, `sw.js`, новые файлы) —
   увеличь номер версии `CACHE` в `sw.js` (`hotelki-v1` → `hotelki-v2` и т. д.) и добавь новые
   файлы в список `CORE`.
3. **Офлайн.** Всё должно работать без сети: никаких новых внешних зависимостей, кроме уже
   подключённых Google Fonts (Unbounded, Onest — они кэшируются) и GitHub Gist API для
   синхронизации (необязательной: без неё приложение работает как раньше). Никаких своих
   серверов и других API.
4. **Интерфейс.** На русском, типографские кавычки «ёлочки». Рассчитан в первую очередь на iPhone:
   safe-area, крупные тап-зоны, светлая и тёмная тема.
5. **Без сборки.** Никаких сборщиков, npm и фреймворков — чистый HTML/CSS/JS, чтобы GitHub Pages
   отдавал файлы как есть.

## Как работаем

- Владелец пишет, что хочет поменять, коротко и разговорно. Если непонятно — задай один
  уточняющий вопрос, а не делай наугад.
- Перед заметными изменениями напоминай сделать «Сохранить копию» (вкладка «История»).
- Коммить сразу в `main` с понятным сообщением на русском и отправляй в origin — GitHub Pages
  обновится сам.
- После изменений коротко скажи, что поменялось и что сделать на телефоне (обычно: подождать
  минуту-две, закрыть приложение и открыть снова с интернетом).
- Материться в ответах можно, владелец не против.
